# 开启自动同步

已配对的两台手机，各做一次下面的操作。不需要重新配对，不需要导入 JSON。

1. 在旧 Google Drive 渠道最后同步一次。进入「设置 → 自动同步」，勾选允许补传，点「开启自动同步」。
2. 保存下载的备份。iPhone 如果跳到了文件预览或分享页面，保存后回到 LifeOS，点「备份已保存，继续」。
3. 保持联网，Windows 归档程序保持运行。后面的补传、校验、电脑完整备份和开启由程序自动完成；另一台手机也按前两步操作即可。

看到「自动同步已开启」后，正常记录即可。前台自动同步，完全关闭的手机会在下次打开并联网时补领。

## 等待时怎么办

- 「本机已准备好」：去另一台手机开启；两台都准备好后等待电脑归档，无需手动正式切换。
- 「还在等旧录音或附件」：在曾经保存原件的设备也开启同步。程序会自动重试，不用重复下载备份。查看「同步详情」可找到具体文件编号。原件真的丢失时不能凭空恢复，也不能跳过校验宣布成功。
- 连接失败：本机内容保留，回到前台联网后重试。已确认保存的备份不会要求重复下载。
- 备份后关闭了应用、尚未点继续：再次开启时可能重新下载一次，这是为了避免把未保存的文件算作已备份。

配对、空间编号、撤销设备及手动切换保留在「高级设置」。旧版代码和发布包保留，回退点为 `pre-migration-progress-20261117`；更早的升级前版本见 [回退说明](PRE-AUTOSYNC-ROLLBACK.md)。

## 实现和安全门槛

首次备份回调必须等用户明确确认保存，之后才保存本地摘要及开启意愿。前台每 15 秒继续迁移，重试复用来源备份，不反复下载整个 JSON。来源备份是迁移前资料，不冒充全局合并完成的备份。

两台非撤销 PWA 明确选择开启后，仍须各自在当前云端 head 完整核验。Windows Agent 完成 SQLite、原始操作和全部媒体的持久归档，生成独立完整 SQLite/媒体备份并校验媒体清单，提交当前 head 的备份摘要后，才请求自动启用。服务端再次检查全部门槛；并发变更使旧 head 失效时继续重试。旧手动切换入口兼容，自动开启比旧入口增加了明确意愿和完整电脑备份条件。

进度和错误不因输入框持有焦点而隐藏。主界面只显示可理解的下一步，技术原因保留在同步详情。Google Drive 仍手动；数据库名称、业务模型、因果合并、多计时器、MCP 和通知不改变。

真实 iPhone 文件保存/返回、Android 系统下载交互及个人缺失原件，须在各真机验收；自动化浏览器下载事件不能证明文件已被用户保存。
