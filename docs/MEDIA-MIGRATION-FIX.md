# 历史媒体迁移卡住的修复

2026-11-17 修复“历史媒体尚未完整到达云端”反复出现的问题。修复前版本单独保留在 `pre-media-migration-fix-20261117`；E 盘另有修复前源码标签、发布包、SQLite 一致性备份和实际存在的媒体备份。没有清除业务记录、旧操作日志或设备配对。

## 原因

1. 原传输先要求本机引用的全部历史文件已在云端，再上传自己持有的原件。两台设备各持有一部分文件时会互相等待。
2. 初次迁移的电脑归档又等待 PWA 完整校验通过，无法先贡献电脑持有的原件。
3. 原本机音频交换只读取未删除记录的音频，已删除记录、历史操作引用和非音频附件可能没有进入 Pocket 的媒体表。

旧录音即使不再显示在随手记中，仍可能被保留的操作历史引用。第一阶段要求保留完整历史，不能用忽略这些引用、删除操作或直接标记成功的方式绕过问题。

## 新流程

用户确认最后一次旧 Drive 收敛并允许补传后，先下载本机现有资料的 `before` 备份，再发送签名 `migration/prepare`。服务器只记录开始补传的授权，明确返回 `verified:false`；不产生完整核验记录，也不放行 activate。

电脑 Agent 收到准备授权后，先创建完整电脑备份，再开始贡献本机原件。各 PWA 则先从本机白板恢复可读取的历史附件、上传自己持有的媒体，再领取其他设备的文件。手机不会请求电脑的 `/attachments` 路由。本机恢复同样验证文件名、大小和 SHA，不修改业务记录。

所有原件齐全且本机/云端清单一致后才发送 `migration/verify`；如果补齐后资料发生变化，另外下载 `verified` 完整备份。正式切换仍必须满足两台 PWA 当前完整清单与电脑持久归档一致。

实际缺少的文件会显示具体文件编号；未完成上传与文件大小异常也分别提示。存在不可恢复的原件时继续阻止正式切换，不宣称迁移完整。

同时分离配对与普通请求的限流计数，避免同一网络下的正常读取次数导致新设备被错误拒绝配对；限流本身保留。

## 用户操作

1. 更新电脑和两台手机的 Pocket；保留网站数据和现有配对，无需重新配对。
2. 在原录音设备保持 LifeOS 打开并联网；各设备进入“设置 → 自动同步 → 迁移与设备管理”。
3. 完成最后一次旧 Drive 收敛后，勾选补传授权，点击“下载备份并校验本机”。保存下载的备份；浏览器可能生成 `before` 和 `verified` 两份文件。
4. 给电脑归档程序一个轮询周期（约 45 秒），再在需要的设备重试校验。期间尽量先不新增内容，避免核验的云端版本继续变化。
5. 如果仍显示某个文件编号缺失，需从保留原件的设备或备份补回；重新登录 Google 或反复重新配对不会重建丢失的录音字节。
